# ISO/IEC Quality and Life-Cycle Baseline

## Scope

ISO/IEC references guide product quality, information-security management and software life-cycle processes. The project may align its practices with selected clauses and controls; this repository does not claim certification.

## Reference baseline

- **ISO/IEC 25010:2023:** product quality model to guide quality requirements and evaluation.
- **ISO/IEC 27001:2022:** information security management system requirements; useful as a governance reference if the project later establishes an ISMS.
- **ISO/IEC 27002:2022:** information-security controls guidance.
- **ISO/IEC/IEEE 12207:2017:** software life-cycle processes.

Confirm the applicable edition and amendments from ISO before each formal assessment.

## Product quality

Translate relevant quality characteristics into measurable requirements, including functional suitability, performance efficiency, compatibility, interaction capability/usability, reliability, security, maintainability and flexibility. Select measures that fit each feature and platform.

## Information security

Use a risk-based approach to identify assets, threats, controls, owners and residual risks. Cover access control, cryptography, operations, supplier relationships, incident handling, continuity and compliance where applicable. Do not claim an ISO/IEC 27001-certified management system unless an accredited certification process has actually been completed.

## Software life cycle

Apply controlled processes for:
- requirements and planning;
- architecture and design;
- implementation and code review;
- integration and testing;
- release and deployment;
- operation, maintenance and change;
- retirement and data disposition.

Scale process rigor with risk, while preserving traceability for security- and safety-relevant decisions.

## Evidence

Maintain quality requirements, architecture decisions, test results, risk records, change history, release records and operational procedures. Record deviations and improvement actions.
